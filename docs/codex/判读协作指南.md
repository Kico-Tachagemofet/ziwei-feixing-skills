# 判读协作指南

这份指南帮助 Codex 在既有 pipeline 中发挥判断力。技术要求由 skills 负责；这里关心怎样把已完成的分析变成对用户有用的解读。按本轮占问使用，不固定任何宫位、结论或文风模板。

## 1. 让完整分析长出清楚的主次

接题时，把用户真正想知道的事情保持在视野里。随着盘面、太极和来源逐步明确，沿规定阶段回答：本题最有分量的结构是什么，它怎样作用于当事人，相关领域各自承担什么。

“都看”意味着相关面向得到完整覆盖。按 lens 要求分题以后，在 composition 中把它们放回同一问题：哪些在讲主体，哪些在讲环境，哪些在讲后果或可行方向。主次取自当前合参，不预设乐观或悲观的定调。

把尚未定型的想法留在分析中检验。到了输出判断的阶段，用准确的动词说清它；已经有足够依据的部分，可以自然、直接地对用户讲。

## 2. 在合参中完成判断

主星、辅小星、宫义和四化各有作用。查到原义后，继续完成当前 skill 要求的交叉与合成，说明这些条件放在一起，怎样改变本题中的一件事。把帮助、阻力及各自来源完整保留下来。

一条 finding 应带来能辨认的认识，例如谁推动了什么、哪种相处或做事方式容易出现、事情具体卡在哪里。若摘要仍只说“有联系、要整理、存在不同层面”，利用 skill 已有的回退方式，回到来源、宫职与结构补推导。让成文者收到足够具体的判断和条件。

这里的具体性来自已核实的条件与作用。生活场景用于说明判断；事实、例示和现实反馈各有清楚位置。既保留推论的解释力，也保留来源实际允许的范围。

## 3. 正文替读者完成理解

在 render 阶段，先消化已通过的 composition 与 findings，抓住这一节要回答的事情。正文先说有分量的判断，随后解释它怎样发生，以及哪组配置使它具有这张盘的特点。用必要的星名和白话星性保持辨识度，完整技术链按 skill 放在技术依据中。

展开篇幅时，各段分别增加已成立的原因、表现、差异或影响；跨题引用说明同一结构在另一领域的作用。表格适合比较真实差异，散文适合讲清事情的前后。满足技能要求的细节密度，让每一段都有值得保留的信息。

例如，上游若已支持“文书能建立来往，同时某些说法容易引起分歧”，成文可以这样组织：

> 你的文字能成为别人接近你的入口。交流费力的地方，往往落在某句话怎样被理解：对方可能愿意继续读，也可能仍不同意你的解释。这里既有文书与读者之间建立联系的支持，也有作品、回应引出的言语分歧。

这只是展示“判断—具体表现—必要依据”的写法。具体星组、作用强度与取义，仍须来自当前案例已经完成的推导。

用户要求“讲配置”时，在相应判断旁解释关键星组及其作用；要求技术展开时，再提供相应明细。两种阅读需要可以各得其所。

## 4. 让审计同时面对证据和读者

在现有审计职责内，带着实际占问读成品：能否从正文说出本盘的主判断、主要差异及实际困难？再沿技术依据核对，这些话是否确由当前配置和条件支持。

技术核验继续按 skill 完整执行。读者视角帮助识别另一类问题：一个结论虽然处处有引用，却仍适用于几乎任何人；一段虽然更长，却没有增加认识；一份报告虽然覆盖全面，却没有形成整体判断。发现后回到产生问题的阶段修正。

审查时保留自己的判断，允许质疑上游已经通过但仍空泛的表述。把意见落到具体句子、缺失的推理或不当取义上，帮助作者修复实质。

## 5. 把努力放在改变答案的地方

按流程完成必读来源、小星合参和必需审计。额外工作围绕具体疑问开展：它会改变哪个判断，解决哪个来源缺口，或影响哪项交付？问题已经解决，就使用所得结果继续推进。

委派时给出明确子问题、现有证据和交接用途。主代理亲自承担整篇的主次与表达；让协作者提供互补观察。进度汇报讲新发现、待解决的问题与接下来会得到什么，最终交付以解读和必要限制为中心。

## 6. 用反馈修复对应问题

用户说“空泛”，先检查判断有没有具体的人事含义；说“和星不搭”，检查配置到结论的连接是否成立、是否在表达中丢失；说“看不懂”，检查正文是否替读者完成了理解。结合上下文定位，再按 skill 修复相应阶段。

在原任务范围内把修复做完。已经清楚的授权继续执行；会实质改变问题、宫义或工作范围的未决歧义，再提出聚焦的问题。每次反馈使这份交付更贴近所问，而不是自动生成一套新的规则。
